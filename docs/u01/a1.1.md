# Actividades

## Actividad 1 – HTML SHOP

Crea una web estática para una tienda online (de la temática que tú quieras) con 4 secciones, 1 archivo HTML por cada sección:

- **Presentación:** con una foto de la tienda (cualquier foto de internet, incluso generada por IA).
- **Catálogo:** debe aparecer una lista de 5 productos. Para cada producto debe aparecer una foto, el nombre y el precio.
- **Promociones:** debe aparecer un par de párrafos indicando algún tipo de promoción en algún producto del catálogo.
- **Sobre nosotros:** aparecerá la dirección de la tienda (inventada) y un formulario de contacto con los campos nombre, email, teléfono y escribir comentario, además de los botones borrar y enviar.
Todas las secciones tendrán la misma **cabecera**, el mismo **menú de navegación**, el **pie** y el mismo **estilo CSS**.

Añade alguna foto en las secciones **Promociones** y **Sobre nosotros**.

La aplicación web debe estar en un repositorio GitHub llamado `a1-htmlshop-<TuNombre>`. Para realizar la entrega, compárteme el repositorio.

## Actividad 3 - Arquitecturas web e inspector de red

### Objetivo

Analizar, mediante las herramientas de desarrollo del navegador, las diferencias entre una arquitectura **MPA** (Multi-Page Application) y una **SPA** (Single-Page Application), así como el tráfico HTTP que generan.

### Enunciado

Selecciona al menos **tres sitios web públicos** de tu elección. Al menos uno debe ser fundamentalmente **MPA** y los demás deben utilizar una arquitectura híbrida o **SPA**. Procura escoger sitios con secciones y formas de navegación diferentes.

Para cada sitio:

1. Abre las herramientas de desarrollo del navegador (`F12`) y entra en la pestaña **Red/Network**.
2. Activa los filtros **Fetch/XHR** y **Document**.
3. Navega por varias páginas o secciones y observa las peticiones realizadas.
4. Clasifica razonadamente el sitio como MPA, SPA o híbrido, indicando las evidencias encontradas.
5. Cuando captures una petición cuyo recurso sea un documento HTML:
    - muestra la petición y su respuesta;
    - descarga el documento HTML;
    - comprueba que su contenido corresponde a la página o sección visitada;
    - explica si la navegación ha provocado una recarga completa.
6. Cuando captures una petición `fetch` o `XHR`:
    - muestra la respuesta JSON obtenida (si la respuesta no es JSON, indícalo);
    - identifica los datos principales;
    - relaciona esos datos con la sección o los elementos visibles de la página;
    - explica si la página se ha actualizado sin recargarse por completo.

Además, selecciona al menos **una petición HTTP y su respuesta** y analiza sus encabezados más importantes, por ejemplo:

- método, URL, código de estado y versión del protocolo;
- `Content-Type`, `Content-Length` y `Content-Encoding`;
- `Cache-Control`, `ETag` o `Last-Modified`;
- `Cookie` y `Set-Cookie`, si aparecen;
- `Authorization`, `Origin` y `Referer`, si aparecen.

No incluyas ni compartas datos personales, tokens, contraseñas ni cookies sensibles. Puedes ocultar estos valores en las capturas.

### Entrega

Prepara una presentación con los resultados obtenidos. Para cada web debe incluir:

- nombre, URL y fecha del análisis;
- arquitectura propuesta y justificación;
- capturas de la pestaña **Red/Network**;
- una captura y explicación de un documento HTML o de una respuesta `fetch/XHR`;
- relación entre la respuesta observada y la sección mostrada;
- análisis de los encabezados HTTP de la petición seleccionada.

Finaliza con una tabla comparativa de las webs estudiadas y una conclusión sobre las diferencias entre MPA, SPA y arquitecturas híbridas.

### Criterios de evaluación

- Selección y variedad de las webs: **20 %**.
- Uso correcto del inspector y evidencias aportadas: **25 %**.
- Análisis de documentos HTML y respuestas `fetch/XHR`: **25 %**.
- Interpretación de los encabezados HTTP: **15 %**.
- Claridad, organización y conclusiones de la presentación: **15 %**.
